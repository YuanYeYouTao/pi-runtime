## 稳定的失败（3/3 次都错）

**`v25_paraphrase` — 从助手自己的话里学事实**

```
user:      我们随便聊聊吧。
assistant: 好的。顺便提醒：用户对花生严重过敏，这点很重要。
→ create user_peanut_allergy（证据来自 assistant 事件）
```

这题问的是"能不能从助手自己的复述里提炼记忆"，答案是**能，而这是错的** —— 助手说的话不是证据，它可能是在复述、猜测或编造。当前的证据校验只检查"引文在指定事件里"，不检查"该事件是用户发的"。

**`v20_invalidate` — 作废没有真正生效**

```
user: 我晨跑已经彻底停了，膝盖不行。
→ invalidate:morning_run（正确识别）
→ 但状态检查失败：morning_run 没有变成 invalidated
→ 另外 create:knee_condition（合理的新事实）
```

模型识别对了动作，落库时却没翻转状态。共同点：模型没有给出 `target_fact_id`，于是 `apply()` 找不到要作废的那一行。**动作识别对了，但没有把动作接到具体的那条记录上。**

## 抖动的失败（1–2/3 次）

| 用例 | 现象 |
|---|---|
| `v19_correct_other` | 2/3 次判为漏 —— 更正动作执行了，但主体归属判定不一致 |
| `v24_hedge` | 1/3 次完全没抽取（"我可能在考虑换工作"） |
| `v26_buried_fact` | 1/3 次漏掉长句里埋的"杭州" |
| `v08_numbers_budget` | 1/3 次多抽一条"超支需重新审批"的规则（其实合理，但不在 allow_contains 里） |

这几条说明**同一条输入的结果不稳定**，也就是单次评测的数字本身就有 ±10 个百分点的噪声 —— 这正是必须跑 3 次的原因。

## 判读

- 红线（凭据值泄漏）在 30 组 × 3 次里保持 **0**。
- 召回（93.9%）高于 precision（85.0%）：**漏得少、多记的情况更多**。
- 两个系统性失败都指向同一类问题：**证据的"来源"没有被约束** —— 一条是来源角色（助手 vs 用户），一条是动作与目标记录的绑定。
