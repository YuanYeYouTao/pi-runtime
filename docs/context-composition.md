# 上下文编排方案

> 目标：把"上下文"从一个字符串拼接，变成一次**有预算、可解释、可评测的资源分配**。

## 1. 目标与非目标

**目标**

- 每一轮 prompt 都由一个显式的 **composition plan** 生成：谁入选、为什么、占多少 token、什么被丢掉。
- 预算是最硬约束。超出时按**确定的淘汰顺序**丢弃，而不是碰运气。
- 同一事实出现在多处（记忆 / 摘要 / 窗口 / 检索）时只出现一次。
- 冲突有明确裁决规则，且裁决可被事后审计。
- 能用一组离线实验量出"多给 1000 token 换来多少召回"。

**非目标（明确不做）**

- 不做向量检索（数据量不够，收益测不出来；先留接口）。
- 不做"让模型自己挑上下文"（不可复现、不可预算）。
- 不做多轮 agent 相互传上下文（那是子 Agent 的事，另立方案）。

## 2. 现状（起点）

`src/worker.ts` 里手写四段拼接：

```
① 长期记忆（memory.contextBlock，1800 字符）
② 滚动摘要（thread_state.summary，≤1200 字符）
③ 最近窗口（buildConversationContext，6 条 / 4000 字符）
④ 当前消息
```

问题：预算分散在各自模块里、没有统一淘汰顺序、没有去重、没有冲突裁决、没有"为什么这么拼"的记录。

## 3. 架构：compose 一次，渲染一次

```
collect()  →  candidates[]       每段候选带元数据（来源/置信度/时间/相关性）
   ↓
rank()     →  段内排序           记忆按 confidence×importance×recency；窗口按新近
   ↓
allocate() →  预算分配           每段 floor / cap / 弹性
   ↓
dedupe()   →  跨段去重           语义重复只留一处（保留优先级高的）
   ↓
resolve()  →  冲突裁决           同槽位冲突时窗口胜出，并记录 conflict
   ↓
render()   →  固定顺序 + 分隔符
   ↓
manifest   →  落事件（入选/丢弃/原因/token）
```

纯函数边界：`compose(inputs) → { prompt, manifest }`，不碰数据库、不调模型，可单测。

## 4. 段落策略

| 段 | 来源 | floor | cap | 淘汰方式 |
|---|---|---|---|---|
| 指令 | 配置 / 系统提示 | 固定 | — | 永不淘汰 |
| 长期记忆 | `memories`（仅 `active`） | 200 | 900 | 按 confidence 从低往高丢 |
| 会话摘要 | `thread_state.summary` | 0 | 1000 | 超帽时重新压缩，不截断 |
| 最近窗口 | `conversation_events` | **1200** | 2800 | 从最旧开始丢 |
| 检索片段（可选） | 事件检索 | 0 | 800 | 按相关分丢 |
| 当前消息 | `task.prompt` | — | **不限** | 永不淘汰 |

规则：

1. **floor 先满足**，剩余预算按各段"剩余需求"比例分配。
2. `最近窗口` 有 floor：宁可压缩摘要，也不能让最近对话缺席。
3. `当前消息` 无上限：用户这一句永远完整进入。

## 5. 排序

- **记忆**：`score = confidence × (importance/5) × recency_factor`，`recency = 0.5^(ageDays/180)`。同分按 key 稳定排序（保证可复现）。
- **窗口**：不排序，只保留时间序（顺序本身是信息）。
- **检索**（若启用）：`0.6 × 词法分（bigram Jaccard）+ 0.4 × recency`，**不用向量**。

## 6. 去重

同一个断言可能同时出现在记忆、摘要、窗口里。

- 归一化（去空白/标点/小写）+ bigram Jaccard ≥ 0.7 视为重复。
- **保留优先级**：窗口（原文）> 记忆（结构化）> 摘要（压缩）。
- 丢弃时在 manifest 记 `dedup: {keptFrom, droppedFrom, similarity}`。

理由：窗口里的原话信息量最高；记忆的价值在于**跨会话**，同一轮里重复没有意义。

## 7. 冲突裁决

触发条件：同一 `key` 在记忆与窗口里内容不一致（相似度 < 0.4 且 key 相同）。

裁决顺序：

1. **窗口胜**（用户刚说的 > 之前记的），记 `context_conflict` 事件，**不自动写记忆**。
2. 记忆行标 `note`（不是改状态）："本轮与用户最新表述冲突"。
3. 交给下一轮 distill 用四态裁决处理（那才是写路径的唯一入口）。

理由：读路径不能写数据，否则一次模型误判就永久污染记忆。

## 8. 预算与淘汰

总预算 = `context budget`（默认 6000 字符 ≈ 1700 tokens，可配）。

超预算时的淘汰顺序（**固定，不随机**）：

```
检索片段 → 低置信度记忆 → 摘要（重压） → 最旧窗口 → 高置信度记忆
```

永不淘汰：当前消息、指令。

token 估算：`chars / 3.5`（中英混合的经验值）。**每 50 次运行用 provider 真实用量做一次校准**，把 ratio 写回配置，避免长期漂移。

## 9. 渲染格式

顺序（重要信息靠两端，模型对首尾更敏感）：

```
## 指令（若有）
## 长期记忆（跨会话，可能过时）
- [偏好·3] …
## 已压缩的更早对话
## 最近对话（按时间顺序）
[Rick] …
[助手] …
## 当前消息
…
```

每个段带一句**用途说明**，防止模型把"记忆"当"当前指令"。段之间用 `---` 分隔。

## 10. Manifest 与可观测

每次运行落一条 `context_plan` 事件：

```json
{
  "budget": 6000,
  "used": 5432,
  "segments": {
    "memory":   {"ids": [5,4,3], "chars": 205, "dropped": [7], "reason": "low-confidence"},
    "summary":  {"chars": 443, "version": 12},
    "window":   {"ids": [40,41,42], "chars": 1200, "dropped": [38,39], "reason": "budget"},
    "retrieved":{"ids": [], "chars": 0}
  },
  "dedup": [{"kept": 42, "droppedMemory": 9, "similarity": 0.83}],
  "conflicts": [],
  "estimateRatio": 3.42
}
```

`pi-rt context <task-id>` 能打印这份计划 —— 这是"为什么它答错了"的第一手材料。

## 11. 评测

复用现有 `eval-context`（基线 vs 系统），新增两类实验：

**A. 预算敏感度扫描**

```
for budget in [2000, 4000, 8000, 12000]:
    for turns in [2, 6, 12]:
        run 10 用例 → 记录 (recall, avg tokens)
```

产出"召回 vs token"曲线，回答：多给 1000 token 值不值。

**B. 编排消融**

| 变体 | 关掉什么 | 想证明 |
|---|---|---|
| full | — | 基准 |
| no-dedupe | 去重 | 去重省了多少 token、掉不掉召回 |
| no-summary | 摘要 | 摘要对长会话的贡献（已测：0/5 → 5/5） |
| window-only | 记忆 + 摘要 | 纯窗口的上限 |

**红线断言**（纯代码，不靠模型）：`tentative` 与 `contested` 的记忆行**一条都不许出现在 prompt 里**。

## 12. 分阶段实施

| 阶段 | 内容 | 预估 | 验收 |
|---|---|---|---|
| P1 | 抽出 `src/compose.ts`，行为与现在**完全一致** | 半天 | 现有 5 套评测结果不变（parity） |
| P2 | 段落 floor/cap、淘汰顺序、跨段去重 | 半天 | 新增去重单测 + manifest 字段齐全 |
| P3 | 冲突裁决、预算超限保护、token 校准 | 半天 | 冲突用例 + 超预算用例 |
| P4 | （可选）检索段 | 1 天 | 扫描实验显示召回提升 |

**P1 的关键**：先做"零行为变化"的重构。否则一旦改了行为又改了结构，出问题无法归因。

## 13. 风险

| 风险 | 缓解 |
|---|---|
| 重构成隐蔽回归 | P1 用 parity 评测锁死 |
| 预算太小导致关键信息被丢 | floor 机制 + 扫描实验定预算 |
| 去重误删（把两个不同事实判成重复） | 阈值 0.7 + 只在**跨段**做，段内不去重 |
| 摘要与记忆互相矛盾 | 冲突只记录不写库，交给 distill |
| token 估算漂移 | provider 用量校准，记 ratio |
